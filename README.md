# 空气证据与巡查

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

时刻为东八区；`observed` 为整小时内的观测，`group` 声明共享参考设备、空间或重复路线导致的相关证据。`observations.value=null` 与 `flag` 要一起解读，低于检出用从 0 到 `lod` 的范围，停机不填补。固定监测计划按 `zones` 的日内小时覆盖和独立证据组下限判定常规日指标。颗粒指标单位统一为微克每立方米；这里只使用资料中的登记阈值，不引用真实标准。超过阈值的连续小时可跨日；一小时停机形成事件证据缺口，不自动确定有效或失效。正好等于阈值不算超过。
`calibration` 的校准加性误差用闭区间记录，适用期为左闭右开；撤销通过 `revokes` 关联旧编号。常规资料需是计划采样或已备案的相同抽核设计；针对性路线带来的读数仅支持事件。巡查角色按 `patrol_options` 的时窗、车辆及路线可达范围排班，当有重叠证据组时按待确认事实而非报警条数衡量覆盖。已经发车的一班不计为可重新分配；如回来未覆盖目标小时，回执不代表完成核查。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联。当前仓库只包含业务来源资料及检查，尚无分析结果或业务操作入口。
